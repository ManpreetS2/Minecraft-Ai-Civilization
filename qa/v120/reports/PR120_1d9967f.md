## Findings (none blocks provisional offline integration)

* **QA120-L1 (Low) — type-coercion of the report run id.** `String(report.runId ?? report.attribution?.runId ?? report.experimentId ?? "")` accepts a top-level `runId` of `["<run id>"]` (a one-element array stringifies to the id). Requires a forged local report, and a fully coherent local forgery is already accepted by design (T26), so this is hygiene, not an authenticity break. The coercion itself predates PR #120; the new `attribution.runId` read adds one more place it can occur. The attribution field itself is checked with strict `!==` in `evidence-consistency.ts` and is not affected.
* **QA120-L2 (Low) — a hostile non-string `attribution.runId` crashes the verifier instead of producing an error.** `{"toString":"x"}` makes `String()` throw `TypeError` inside the consistency check. Fails closed (no PASS), but as an exception rather than a rejection. Pre-existing line, not changed by #120.
* **Open duplicate-event contract (PR #104, disclosed, not a #120 regression).** One completed physical withdraw or deposit emits **two** `ItemWithdrawn` / `ItemDeposited` events (`qa/v120/defects/qa120-duplicate-events.test.ts`, 2 red). Physical conservation and the unsuccessful-result rules are unaffected. I deliberately excluded duplicate counts from the passing sweep so they cannot be mistaken for a pass.
* **QA78 obsolete bread-zero rollback assertion (disclosed).** `qa/v78/test/qa78-lifecycle.test.ts:243` still asserts `bread === 0` after an unsuccessful withdraw. It stays red (unchanged). The replacement contract (QA88: conservation, no success event, authoritative stock not rewritten, PENDING reconciliation) passes: `qa/v88` defects 4/4.
