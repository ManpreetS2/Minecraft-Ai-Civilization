## Verdict: **PASS for the requested repair, with two tracked non-blocking findings.**

Abandoned personal and household chest operations **cannot emit a false success event** and **cannot release a lease that a newer action refreshed**; the physical transfer stays visible as a PENDING observation; no inventory is rolled back or hidden; no store row is written. The patch introduces one small **liveness regression** (a cooperative cancel now leaves the container lease held until its 30 s TTL, QA103-L1) and leaves two cosmetic reconciliation issues. None blocks a first controlled smoke; QA103-L1 should be fixed before a 2v2 run that shares one communal chest.

## 2. Findings

| ID | Sev | Defect |
|---|---|---|
| **QA103-L1** | Low-Medium; **regression introduced by #103** | `finally` now releases the claim only `if (storageActionCurrent(ctx))`. A **cooperative cancel** (caller abort; the skill returns inside the grace) also makes the frame non-current, so the container lease stays held by the cancelled citizen until its 30 s TTL. On PR #88 the lease was released (verified: PR #88 shows none after unwind, PR #103 shows `citizen_atlas`). Effect: any cancel (disconnect, death, preemption, shutdown) blocks every other citizen from that chest for up to 30 s; the same citizen can refresh it. Minimum fix: release by **claim token**: record the acquisition id when `tryClaim` succeeds and release in `finally` iff that exact claim is still ours, instead of skipping when the frame is not current. That keeps the refreshed-lease protection and removes the regression. |
| QA103-L2 | Low (noise) | A cancellation that moved **nothing** (a signal already aborted when the action is scheduled) still emits PENDING `AbandonedActionObservation` records whose observed result is a failure. There is nothing to reconcile. Fix: emit the pending record only when the observed result indicates a possible physical effect (`success`, or data with a moved count). |
| QA103-I1 | Info | One abandoned transfer leaves **two** `AbandonedActionObservation` records: one from `home-ops` with the real result and one from the executor tail gate wrapping the already-CANCELLED result (the tail gate fires again because the frame is still non-current). A reconciler must de-duplicate by action; better: let the tail gate skip a result that is already an abandoned observation. |
| QA103-I2 | Info (my own test hygiene) | PR #103's gate run shows `qa/v88` regression at **25/26**: my QA88 source tripwire scans `packages/*/dist/*.d.ts` once `pnpm build` has run, so it fails for a reason unrelated to production (it passed 26/26 before a build, which is when the author ran it). Not a defect in #103. My QA103 copy excludes `dist/`; the PR #95 test should be patched the same way. |
| Not exercised | A success event followed by abandonment inside the same tick (the skill emits while current, the executor check runs a microtask later): physically accurate, narrow, source-read only. |
