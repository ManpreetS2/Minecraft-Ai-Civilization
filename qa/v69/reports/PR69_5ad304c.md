## 4. `action-boundary.ts` and the "no owner" gap

**The guard cuts writes from an action whose owner is inactive. It allows any write when no owner exists.** Measured with the production `createActionBoundary` and `installPacketGuard`:

* **Contained (late writes refused):** `setTimeout`, `setInterval`, promise `.then`, `await` continuation, `queueMicrotask`, `process.nextTick`, `setImmediate`.
* **NOT contained:** a listener registered inside the action on a long-lived emitter and fired from a context with no owner (a socket read, a physics timer). It passes.
* **The cut-off is not at `abort()`.** A write in the same synchronous turn or one microtask after abort still passes. Writes about 10 ms later are refused.
* **Packets outside the guard set** pass after abandonment: `craft_recipe_request`, `select_trade`, `enchant_item`, `pick_item`, `set_creative_slot`, `update_sign`, `chat_command` and `chat_message`. Position, look, `entity_action` and similar are also unguarded, so an abandoned skill can still steer the body.

**Can a production callback exploit the gap? Yes.** `runMineflayerFishCycle` registers `bot._client.on("entity_metadata"/"world_particles")` listeners that call `bot.activateItem()` (`use_item`) with no abort check. Deterministically (fake timers, owner provably inactive, bite packet 5 ms after abort), the late `use_item` **reached the wire** (QA69-M3). The pathfinder's `physicsTick` handlers are structurally the same pattern, but I could **not** exercise `mineflayer-pathfinder` offline, so that part is unproven.

**Real Mineflayer was not exercised end to end.** No Mineflayer client or server ran. Real Mineflayer code was run in exactly one place: the `digging.js` plugin, in a child process against a stub bot (QA69-L3). Everything else uses controlled doubles.

## 6. Correction instructions

1. **M2 (blocking).** Allow bounded cleanup after deactivation: exempt the cancel-retrieve, or perform it before `owner.active` flips (for example a cleanup hook the boundary runs first). Flip the M2 test to a normal `it`.
2. **M3.** Do not rely on ALS alone for listener callbacks. Capture and check the owner inside the fish `reelOwnBite` path (check `opts.signal?.aborted` before `activate`), or detach the listeners in the abort handler synchronously.
3. **M1.** In `validateBuiltStructure`, return `interrupted` whenever `ctx.signal?.aborted` after any navigation, door or move, not only in the chest step. Never set `BLOCKED` from an aborted navigation result.
4. **L1.** After `takeOutput` succeeds, skip `takeInput`/`takeFuel` when aborted, or run them as exempt cleanup. If an abort arrives after `takeOutput`, report success.
5. **L2.** Fence skill events with the owner (drop or tag events emitted after abandonment), or have the boundary expose an `abandoned()` predicate.
6. Add Linux/Windows CI. The guard depends on `AsyncLocalStorage` and timing.
