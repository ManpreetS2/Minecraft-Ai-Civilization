# Independent offline runtime startup

Base: #27, 4da60f0db19db4d48233963e00016ad7f7ef87b5. Branch: agents/t3-independent-runtime-startup.

Normal AgentManager.start previously always sliced DEFAULT_CITIZENS, so the earlier routed tests had to attach custom citizens at the tick boundary. It also generated an unrelated random run ID even when a provider experiment supplied SIM_RUN_ID. This proposal accepts a trusted explicit roster, validates unique IDs and case-insensitive valid Minecraft usernames, prevents partial roster startup or persisted username rebinding, snapshots roster inputs and uses the configured stable run ID. The existing roster path remains available without the hook.

A typed body-construction hook lets tests exercise normal manager startup without Minecraft connections. It is not exposed to models, tools or HTTP. A reproduced follow-up found new roster identities had no persisted personality because initialization preceded row insertion. New rows now exist before deterministic per-citizen personality initialization; tests require persisted, distinct personality records before connection completes. Original legacy rows are preserved.

apps/orchestrator/src/independent-offline-runtime.ts composes the real registry, manager, roster, shared experiment budget and explicit session store. It requires strict assignment parsing, matching two/four citizen counts, equal model-family counts, two equally sized authenticated communities, independent names and an explicit run ID. It accepts injected fixture transports, secret resolution, store and bodies only; allowPaidRequests is always false. There is no implicit file open, secret lookup, family-derived community permission, global provider fallback or live CLI enablement. The normal CLI remains hard-refused by #26. Trusted injected transports are code, not an adversarial network sandbox.

Normal start is tested for both 1v1 and 2v2, including mixed-family communities: real planning/execution/skills acquire berry drops, physically consume simulated food (7 -> 9), gather logs or obtain a pickaxe/table according to distinct scripted provider choices. Private source-authorized memories enter only the owner's provider prompt. Provider evidence and manager persistence have the same run ID. Bodies, navigation, Minecraft world and provider replies remain simulated; no live autonomy claim.
